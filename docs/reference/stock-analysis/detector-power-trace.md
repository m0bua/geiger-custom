# Живлення детектора: траса запуску та повного вимкнення

Джерело: `../source-material/Port-4.1.17(3).hex`, SHA-256
`89368e9b3d8789d641d0d9756971cea92ea10902ea8feffac604745a0791d6d0`.
Перевірено контрольні суми Intel HEX. Усі 64 908 байтів даних HEX збігаються
з байтами дизасембльованого `.pio/stock.bin`. Чотири байти прогалини
`0x0800EF44`–`0x0800EF47` не задані HEX і до аналізованих інструкцій не належать.

## Висновок

**PA5 — найсильніший кандидат на active-high enable живлення детектора/HV.**
Код доводить його поведінку on/off і режим виходу; електричний зв’язок
з високовольтним генератором залишається гіпотезою до апаратної перевірки.
Сигнал може живити також інші частини вимірювального вузла.

| Стан | Адреса виклику | GPIO / mask / state | Результат |
|---|---|---|---|
| Початковий GPIO init | `0x08002E1C` | `0x50000000 / 0x8963 / 0` | PA5=low, разом з іншими виходами |
| Налаштування виходу | `0x08002E76` | GPIOA, Pin=`0xC963`, Mode=1, Pull=0, Speed=0 | PA5 є push-pull output, без підтяжки, low speed |
| Запуск активного режиму | `0x08003956` | `0x50000000 / 0x20 / 1` | PA5=high |
| Пробудження зі стану off кнопкою PB9 | `0x08003494` | `0x50000000 / 0x20 / 1` | PA5=high |
| Повне вимкнення | `0x0800367C` | `0x50000000 / 0x20 / 0` | PA5=low |
| Завершення повного вимкнення | `0x08003714` | виклик `0x0800595C`, r0=1, r1=1 | Перехід у STOP через WFI |
| Звичайне гасіння LCD | `0x08004504`–`0x08004596` | Немає запису в PA5; змінюються RGB, PB8, PB2, LCD SLPIN і тактування | Живлення, кероване PA5, зберігає попередній стан |

## Аргументи HAL_GPIO_WritePin

У `0x08005896` r0 — база GPIO, r1 — маска pin, r2 — state.
При r2!=0 записується BSRR (`+0x18`), при r2=0 — BRR (`+0x28`).
Це записи логічного рівня GPIO; HEX не встановлює, яка напруга при цьому
виникає на трубці.

Ввімкнення з початкового шляху активного режиму:

```asm
08003950  movs r2, #1
08003952  movs r1, #32       ; pin mask 0x20 = PA5
08003954  movs r0, r4        ; r4 = 0x50000000, GPIOA
08003956  bl   0x08005896
```

Цей блок виконується з гілки `0x0800392E`, якщо байт стану за адресою
`0x2000006C` дорівнює 3 (`0x080038C8`–`0x080038CE`). Інакше запуск
проходить через функцію повного вимкнення `0x08003648` і очікування пробудження.

Пробудження: в EXTI callback `0x0800341C` гілка PB9 перевіряє прапорець
стану off за `0x20000118`, відновлює тактування/периферію, змінює прапорці
і піднімає PA5. r2=1 встановлено в `0x08003486`; до запису немає викликів,
які могли б зіпсувати r2:

```asm
08003486  movs r2, #1
          ; записи прапорців RAM
0800348E  movs r0, #160
08003490  movs r1, #32
08003492  lsls r0, r0, #23   ; GPIOA = 0x50000000
08003494  bl   0x08005896    ; PA5=high
```

Повне вимкнення починається у `0x08003648`; після зупинки периферійних
операцій опускає PA5, ще до індикації вимкнення, LCD SLPIN та STOP:

```asm
08003674  movs r0, #160
08003676  movs r2, #0
08003678  movs r1, #32
0800367A  lsls r0, r0, #23   ; GPIOA
0800367C  bl   0x08005896    ; PA5=low
```

## Чому це не SPI1 SCK і не програмний PWM на PA5

Стоковий SPI1 MSP init (`0x0800471E`–`0x08004748`) задає GPIOB,
Pin=`0x38` (PB3/PB4/PB5), Mode=2, Alternate=0. PA5 залишається звичайним
GPIO output з початкової конфігурації `0x08002E76`.

Стоковий PWM таймера, ініціалізованого за `0x08003088`, використовує
TIM2 (`0x40000000`), канал 4 (аргумент 12), а його post-init у
`0x08004814`–`0x08004854` конфігурує PA3 AF2. Це не PA5.
Знайдені переходи PA5 — сталий low/high; алгоритм регулювання HV вони
не розкривають.

## Відмежування від інших сигналів

- **PB6 — точка входу імпульсів, яку слухає сток.** GPIO init викликає
  `HAL_GPIO_Init(GPIOB, ...)` за `0x08002EDA` з pin mask `0x40`, режимом
  `0x00210000` (переривання за спадним фронтом) і pull-up=1. HAL кодує порт B
  у поле EXTI6 регістра `SYSCFG_EXTICR2` (`0x4001000C[11:8] = 1`), вмикає
  EXTI6 falling trigger і unmask для EXTI6. NVIC отримує IRQ7
  (`EXTI4_15_IRQn`) у `0x08002EF2`–`0x08002EFE`.
- Запис IRQ-вектора з індексом 16+7 за адресою `0x0800005C` дорівнює
  `0x08004A25`, тобто Thumb-вказівник на ISR `0x08004A24`. ISR читає
  `EXTI_PR` (`0x40010414`), перевіряє pending bit `0x40`, очищає його
  записом `0x40` і викликає callback `0x0800341C` з аргументом `0x40`.
- Callback гілки `0x40` у `0x0800349A`–`0x080034BE` збільшує 32-bit і
  16-bit лічильники, а також один елемент кільцевих лічильників. Це стоковий
  шлях обробки імпульсу; фізичний провід/підсилювач між трубкою та ніжкою MCU
  HEX не показує.
- PB7 встановлюється high у `0x08002E3E` і `0x0800387A` перед LCD init.
  У попередній примітці його помилково назвали PB14: інструкція
  `0x08002E3A movs r1,#128` заново задає mask=`0x80`.
- PA14 встановлюється high при GPIO init, запуску, пробудженні та в main loop.
  Відповідного low при повному вимкненні в дослідженому шляху немає.
- PB2 і PB8 опускаються й на шляху гасіння LCD, тому цей перехід сам по собі
  не означає вимкнення трубки.

Кастомна прошивка тепер відтворює стоковий активний стан PA5: спершу
записує high у BSRR, тоді задає PA5 як звичайний GPIO output. Лічильник
залишається на PB6/EXTI6 falling. Це контрольований тест стокової поведінки;
роль PA5 як enable детектора/HV досі є гіпотезою, а фактичний результат на
трубці потребує перевірки після прошивки.
