# Geiger-2 custom firmware — handoff package

**Зріз вимог:** 2026-10-16  
**Стан:** специфікація та макети; додано початковий каркас тестової прошивки для RGB LED і кнопок, але збірка та апаратна поведінка ще не перевірені.

Цей пакет збирає погоджені рішення щодо екранів, шрифтів, журналу, налаштувань і застосунку, додає останні рендери та довідкові матеріали зі стокової прошивки. Він призначений для продовження роботи у VS Code.

## З чого почати

1. [VSCODE_HANDOFF](docs/VSCODE_HANDOFF.md) — стан проєкту та план продовження.
2. [PRODUCT_AND_UI](docs/PRODUCT_AND_UI.md) — погоджений вигляд екранів і взаємодії.
3. [LOG_AND_STORAGE](docs/LOG_AND_STORAGE.md) — модель часу, подій та сховища; відкриті рішення позначені явно.
4. [STOCK_FIRMWARE](docs/STOCK_FIRMWARE.md) — факти й обмеження аналізу стоку.
5. [APP_AND_SETTINGS](docs/APP_AND_SETTINGS.md) — опції пристрою та вимоги до JS-застосунку.
6. [OPEN_ITEMS](docs/OPEN_ITEMS.md) — питання перед реалізацією.
7. [REFERENCE_INDEX](docs/REFERENCE_INDEX.md) — покажчик доданих звітів та вихідних файлів.

## Статус доказів

- **Погоджено** — рішення, які користувач зафіксував у цій розмові.
- **Відомо зі звіту** — результат попереднього статичного аналізу або тесту на пристрої; межі доказу вказані біля твердження.
- **Оцінка** — правдоподібна інтерпретація, не підтверджена вимірюванням.
- **Відкрите** — потребує аналізу прошивки або вимірювання плати.

Точний коефіцієнт перерахунку доз, ADC-канали батареї/сонячного входу, GPIO динаміка, RGB та ліхтарика, а також керування HV ще не підтверджені. Нульовий дамп EEPROM не доводить, що всі заводські коефіцієнти зберігалися саме там.

## Важливо щодо довідкових файлів

reference/source-material/Port-4.1.17(3).hex — лише копія для аналізу. Архів legacy-v9-export.zip містить старі патчені HEX та експерименти. Не прошивати їх як кастомну базу: вони створювалися для окремих тестів екранів і не реалізують нову архітектуру.
