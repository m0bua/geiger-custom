# Geiger-2 custom firmware — handoff package

**Поточний стан:** тестова прошивка збирається. На платі підтверджено RGB LED, кнопки, LCD-пікселі, швидку заливку кольором, PWM яскравість LCD/LED і таймаут. Базове керування детектором ще не реалізоване.

Цей розділ збирає погоджені рішення щодо екранів, шрифтів, журналу, налаштувань і застосунку, а також довідкові матеріали зі стокової прошивки. Тут ведеться історія апаратних перевірок компонентів.

## З чого почати

1. [LCD_BRINGUP](docs/LCD_BRINGUP.md) — підтверджений стан дисплея, підсвітки та RGB-керування, разом з історією тестів.
2. [LCD_STOCK_GUIDE](docs/LCD_STOCK_GUIDE.md) — розбір стокової ініціалізації LCD та відмінності, які завадили першому запуску.
3. [VSCODE_HANDOFF](docs/VSCODE_HANDOFF.md) — поточний стан проєкту та наступні задачі.
4. [PRODUCT_AND_UI](docs/PRODUCT_AND_UI.md) — погоджений вигляд екранів і взаємодії.
5. [LOG_AND_STORAGE](docs/LOG_AND_STORAGE.md) — модель часу, подій та сховища.
6. [STOCK_FIRMWARE](docs/STOCK_FIRMWARE.md) — факти й обмеження аналізу стоку.
7. [APP_AND_SETTINGS](docs/APP_AND_SETTINGS.md) — опції пристрою та вимоги до JS-застосунку.
8. [OPEN_ITEMS](docs/OPEN_ITEMS.md) — питання перед реалізацією.
9. [REFERENCE_INDEX](docs/REFERENCE_INDEX.md) — покажчик звітів та вихідних файлів.

## Статус доказів

- **Погоджено** — рішення, які користувач зафіксував у цій розмові.
- **Відомо зі звіту** — результат попереднього статичного аналізу або тесту на пристрої; межі доказу вказані біля твердження.
- **Оцінка** — правдоподібна інтерпретація, не підтверджена вимірюванням.
- **Відкрите** — потребує аналізу прошивки або вимірювання плати.

Точний коефіцієнт перерахунку доз, ADC-канали батареї/сонячного входу, GPIO динаміка, RGB та ліхтарика, а також керування HV ще не підтверджені. Нульовий дамп EEPROM не доводить, що всі заводські коефіцієнти зберігалися саме там.

## Важливо щодо довідкових файлів

reference/source-material/Port-4.1.17(3).hex — лише копія для аналізу. Архів legacy-v9-export.zip містить старі патчені HEX та експерименти. Не прошивати їх як кастомну базу: вони створювалися для окремих тестів екранів і не реалізують нову архітектуру.
