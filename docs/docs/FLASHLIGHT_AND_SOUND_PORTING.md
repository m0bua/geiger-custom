# Geiger‑2: ліхтарик, динамік і звук спрацювання

Дата: 2026-10-20. MCU STM32L051C8T6. Розбір оригінальної EN 4.1.17.

## 1. Результат для перенесення

| Функція | Ніжка MCU | Налаштування | Керування |
|---|---|---|---|
| Ліхтарик | **PB8** | GPIO output push-pull, no pull, low speed | Штатний вимкнений стан — LOW; у UI виконується toggle. Робочий висновок: HIGH вмикає ліхтарик |
| Динамік / звуковий випромінювач | **PA3** | **AF2, TIM2_CH4**, alternate function push-pull, no pull, low speed | PWM1, polarity HIGH |
| Вхід імпульсів трубки, для прив’язки звуку | PB6 | Falling-edge EXTI | Облік імпульсу відділений від озвучення |

Параметри звуку, закладені у стоковому коді:

| Параметр | Значення |
|---|---|
| Частота TIM2 у штатному активному режимі | 32 000 000 Гц |
| TIM2_PSC | 22, тобто ділення на 23 |
| TIM2_ARR | 310, тобто період 311 відліків |
| Значення для TIM2_CCR4 у звуковому буфері | 50 |
| Розрахункова частота PWM | **4 473,647 Гц**, приблизно **4,47 кГц** |
| Розрахункове заповнення | **50 / 311 = 16,08%** |
| HIGH у кожному періоді | Приблизно 35,94 мкс |
| Повний період | Приблизно 223,53 мкс |
| Номінальне вікно озвучення окремої події | **37,5 мс** за логікою запуску/зупинки; фактична осцилограма не вимірювалась |

**Для кастому:** PB8 як звичайний вихід; PA3 як TIM2_CH4 AF2; звук приблизно 4,47 кГц із заповненням 16% та тривалістю приблизно 38 мс. Достатньо PWM та окремого дедлайну вимкнення. DMA не потрібний.

Важливе обмеження: частота, ніжки й регістри підтверджені машинним кодом та емуляцією. Реальний звук на платі в цій сесії не записувався. У стоковій DMA-конфігурації знайдена неузгодженість — див. розділ 5. Тому наведена частота — частота налаштованого PWM, а 37,5 мс — вікно керування з коду, не виміряна тривалість акустичного сигналу.


Дизасембльовано GPIO init, TIM2/TIM21 init, GPIO MSP, DMA init/start, обробник імпульсу, обробник індикації, UI ліхтарика та вимкнення.

## 3. Ліхтарик — PB8

### Докази

- `0x08002DBC`: загальний GPIO init. PB8 входить у маску `0x0D84`, налаштовану як output push-pull, no pull, low speed.
- `0x08002E28`: початковий LOW для маски GPIOB `0x0D04`, до якої входить PB8.
- `0x0800AC4C–0x0800AC64`: гілка короткої події кнопки на головному екрані (`screen == 1`). Скидає подію й викликає `HAL_GPIO_TogglePin(GPIOB, 0x0100)`.
- `0x080036DE`: під час повного переходу в STOP ставить PB8 у LOW.
- `0x08004568`: при переході в інший штатний режим сну також ставить PB8 у LOW.

Це окремий GPIO, **не канал RGB і не PWM підсвітки дисплея**. За програмною поведінкою PB8 відповідає ліхтарику. LOW є штатним станом вимкнення; HIGH як стан увімкнення виведено з цієї поведінки, без прозвонювання транзисторного каскаду.

### Мінімальний перенос через HAL

```c
__HAL_RCC_GPIOB_CLK_ENABLE();

/* Записати OFF до перемикання ніжки в output. */
HAL_GPIO_WritePin(GPIOB, GPIO_PIN_8, GPIO_PIN_RESET);

GPIO_InitTypeDef gpio = {0};
gpio.Pin = GPIO_PIN_8;
gpio.Mode = GPIO_MODE_OUTPUT_PP;
gpio.Pull = GPIO_NOPULL;
gpio.Speed = GPIO_SPEED_FREQ_LOW;
HAL_GPIO_Init(GPIOB, &gpio);

/* ON */
HAL_GPIO_WritePin(GPIOB, GPIO_PIN_8, GPIO_PIN_SET);
/* OFF */
HAL_GPIO_WritePin(GPIOB, GPIO_PIN_8, GPIO_PIN_RESET);
```

Перед повним вимкненням кастому явно встановлювати PB8=0. Наявність GPIO керування не доводить, що світлодіод живиться безпосередньо від MCU; схему силового каскаду HEX не розкриває.

## 4. Звук — PA3, TIM2_CH4, AF2

### GPIO та таймер

Ініціалізація TIM2 розташована за `0x08003088`, timer handle — `0x200002BC`, TIM2 — `0x40000000`.

`0x08004814–0x08004858` виконує post-init GPIO для TIM2:

```text
GPIOA
Pin       = 0x0008  -> PA3
Mode      = 2       -> alternate function push-pull
Pull      = 0       -> no pull
Speed     = 0       -> low speed
Alternate = 2       -> AF2 / TIM2_CH4
```

Параметри з оригінального init:

```text
CounterMode       = UP
Prescaler         = 22
Period            = 310
ClockDivision     = DIV1
AutoReloadPreload = DISABLE
OCMode            = PWM1
Channel           = TIM_CHANNEL_4 (HAL-константа 0x0C)
Initial Pulse     = 0
OCPolarity        = HIGH
OCFastMode        = DISABLE
```

Після виконання оригінального init отримано:

```text
TIM2_PSC   = 0x00000016  (22)
TIM2_ARR   = 0x00000136  (310)
TIM2_CCMR2 = 0x00006800  (PWM1 + preload CCR4)
TIM2_CCR4  = 0
TIM2_CCER  = 0           (канал ще вимкнений)
PA3 MODER = AF; PA3 AFRL = AF2
```

`SystemClock_Config` за `0x08003378` задає HSI16 → PLL ×4 /2 = 32 МГц; AHB/APB1/APB2 без ділення. Оригінальна функція обчислення SYSCLK `0x08005A28` з відповідними RCC-бітами повертає 32 000 000.

```text
PWM frequency = TIM2CLK / ((PSC + 1) * (ARR + 1))
              = 32 000 000 / (23 * 311)
              = 4 473,647 Гц
```

Якщо кастом працює з іншою частотою TIM2CLK, ці PSC/ARR дадуть інший тон. Для збереження тону перерахувати дільники. Використовувати частоту саме таймера; за ненульового дільника APB вона може відрізнятися від PCLK.

### Що відбувається при спрацюванні

1. EXTI PB6 входить у `0x0800341C`, гілка імпульсу — `0x0800349A`. Інкрементує лічильники та `uint32_t pending_indication` за `0x20000450`. PWM тут не запускається.
2. Періодична функція `0x08004A84` перевіряє `pending_indication`. Якщо він ненульовий, скидає його в нуль, обробляє RGB та можливий звук.
3. Звук дозволений, коли byte `0x20000448 != 0` та byte `0x2000043E == 0`. Другий прапорець використовується шляхом сну екрана: сток приглушує цей шлях звуку в такому стані.
4. За `0x08004AFA–0x08004B02` викликається `HAL_TIM_PWM_Start_DMA(htim2, TIM_CHANNEL_4, 0x20000018, 10)`.
5. Якщо на наступному проході pending уже нульовий, гілка `0x08004B08–0x08004B30` вимикає RGB та, якщо звук дозволений, викликає `HAL_TIM_PWM_Stop_DMA(htim2, TIM_CHANNEL_4)`.

У поточному ланцюжку тон не залежить від CPM, рівня або класу кольору. Клас впливає на RGB; звуковий буфер і параметри TIM2 лишаються однаковими.

### Тривалість і часті імпульси

Функція `0x08004A84` викликається обробником TIM21. TIM21 init за `0x08003030` задає PSC=239. Початковий ARR=239 **перезаписується** в основному коді:

- `0x080038BC–0x080038C0`: ARR=4999;
- `0x080039F4–0x080039F8`: ARR=4999 під час відновлення відповідного режиму.

За штатних 32 МГц:

```text
tick = (239 + 1) * (4999 + 1) / 32 000 000 = 0,0375 с
```

Для окремої події програмне вікно між запуском і зупинкою — один такий tick, тобто 37,5 мс. Затримка від імпульсу до запуску — приблизно 0…37,5 мс плюс затримки обробки.

Кілька імпульсів між проходами обробника зливаються в одну звукову індикацію: pending інкрементується, але перевіряється лише як «є/немає». Сам підрахунок імпульсів при цьому виконується окремо. Якщо імпульси приходять у кожному вікні, гілка зупинки не виконується; звук може ставати суцільним. Це не точний аудіолог кожного імпульсу.

У режимах сну ARR/частота системи змінюються. 37,5 мс стосується штатного активного режиму.

## 5. Не копіювати стокову DMA-конфігурацію буквально

У RAM за `0x20000018` лежать 20 halfword-значень `50`, початкові дані Flash — з `0x0800FCC4`. Звуковий виклик передає довжину 10 halfword. У буфері **немає нульового хвоста**, що сам вимкнув би PWM.

Навіть за коректного memory-to-peripheral DMA десять значень не означають «звук лише десять періодів». Callback завершення `0x08007A1C` доходить до порожнього `BX LR` callback `0x08007A1A`; він не вимикає канал TIM2. Подальше вимкнення виконує гілка періодичного обробника.

Додатково в **цьому HEX** DMA init за `0x08004790` містить неузгоджену конфігурацію для PWM:

```text
DMA1_Channel5 = 0x40020044
Request      = 8
Direction    = 0          (PERIPH_TO_MEMORY)
PINC         = DISABLE
MINC         = ENABLE
PSIZE/MSIZE  = halfword
Mode         = NORMAL
```

Виконання оригінального init та звукового виклику дає:

```text
DMA_CCR5   = 0x0000058F   (DIR=0, MINC=1)
DMA_CNDTR5 = 10
DMA_CPAR5  = 0x20000018   (RAM-буфер)
DMA_CMAR5  = 0x40000040   (TIM2_CCR4)
```

Тобто для цього виклику RAM опинилась у CPAR, а регістр таймера — у CMAR з інкрементом. Це не штатна схема запису послідовності PWM у незмінний CCR4. Якщо транзакції обслуговуються, інкрементуватиметься адреса призначення біля CCR4; можливі звернення до інших регістрів/зарезервованих адрес таймера. Сам HEX не доводить, яку осцилограму це реально дає на конкретному MCU.

Висновок: ніжка, частота та значення 50 встановлені; **гарантувати точну акустичну форму оригіналу за цієї DMA-аномалії не можна**. Для кастому відтворювати звукові параметри прямим PWM. Якщо знадобиться DMA, використовувати `MEMORY_TO_PERIPH`, peripheral increment disable та коректні адреси. Для простого кліку це зайве.

## 6. Налаштування кастому

### Ініціалізація звуку через HAL

Фрагмент передбачає глобальний `TIM_HandleTypeDef htim2`, штатний STM32L0 HAL та TIM2CLK=32 МГц. Якщо CubeMX/MSP уже налаштовує PA3 і clocks, об’єднати ці налаштування в одному місці.

```c
__HAL_RCC_GPIOA_CLK_ENABLE();
__HAL_RCC_TIM2_CLK_ENABLE();

GPIO_InitTypeDef gpio = {0};
gpio.Pin = GPIO_PIN_3;
gpio.Mode = GPIO_MODE_AF_PP;
gpio.Pull = GPIO_NOPULL;
gpio.Speed = GPIO_SPEED_FREQ_LOW;
gpio.Alternate = GPIO_AF2_TIM2;
HAL_GPIO_Init(GPIOA, &gpio);

htim2.Instance = TIM2;
htim2.Init.Prescaler = 22;
htim2.Init.CounterMode = TIM_COUNTERMODE_UP;
htim2.Init.Period = 310;
htim2.Init.ClockDivision = TIM_CLOCKDIVISION_DIV1;
htim2.Init.AutoReloadPreload = TIM_AUTORELOAD_PRELOAD_DISABLE;
/* Перевіряти HAL_OK у реальному init. */
HAL_TIM_PWM_Init(&htim2);

TIM_OC_InitTypeDef oc = {0};
oc.OCMode = TIM_OCMODE_PWM1;
oc.Pulse = 0;                       /* тиша після init */
oc.OCPolarity = TIM_OCPOLARITY_HIGH;
oc.OCFastMode = TIM_OCFAST_DISABLE;
HAL_TIM_PWM_ConfigChannel(&htim2, &oc, TIM_CHANNEL_4);
```

Початок кліку: установити CCR4=50, скинути CNT, сформувати update для завантаження preload, запустити канал і встановити дедлайн через 37 500 мкс. Завершення: встановити CCR4=0, завантажити його update, зупинити канал.

```c
/* Початок; виконувати у вибраному аудіоконтексті, не блокувати EXTI. */
__HAL_TIM_SET_COMPARE(&htim2, TIM_CHANNEL_4, 50);
__HAL_TIM_SET_COUNTER(&htim2, 0);
__HAL_TIM_GENERATE_EVENT(&htim2, TIM_EVENTSOURCE_UPDATE);
HAL_TIM_PWM_Start(&htim2, TIM_CHANNEL_4);
/* scheduler: sound_stop через 37 500 мкс або приблизно 38 мс */

/* sound_stop */
__HAL_TIM_SET_COMPARE(&htim2, TIM_CHANNEL_4, 0);
__HAL_TIM_GENERATE_EVENT(&htim2, TIM_EVENTSOURCE_UPDATE);
HAL_TIM_PWM_Stop(&htim2, TIM_CHANNEL_4);
```

Ці фрагменти — приклад перенесення з підтвердженими параметрами, не зібраний і випробуваний на платі модуль. Планувальник, handle, перевірки HAL та взаємодію зі сном потрібно включити у поточний проєкт.

Рекомендована поведінка кастому:

- Лічильник трубки збільшується незалежно від звуку та стану дисплея.
- EXTI лише реєструє імпульс/запит індикації. Звуком керує коротка задача або таймер.
- Режими «вимкнено / лише з увімкненим екраном / завжди» перевіряються перед запуском звуку.
- При новій події під час кліку можна продовжити дедлайн або злити її з поточним кліком. Це вибір кастому; точний аудіоповтор кожної події при високому фоні неможливий за тривалості 38 мс.
- Перед STOP або зміною частоти вимкнути PWM та PB8. Після зміни TIM2CLK відновити потрібну частоту тону.
- Спочатку залишити стокове заповнення 16%; 50% змінить спектр, гучність та навантаження на вихідний каскад.

У звуковому ланцюжку не знайдено додаткового окремого GPIO enable підсилювача. Це не встановлює призначення інших виходів плати, зокрема PB2, і не доводить відсутність спільного живлення периферії.

## 7. Короткий чек для запуску на платі

1. PB8: LOW → HIGH → LOW; перевірити фізичний ліхтарик.
2. PA3 AF2, TIM2_CH4: коротко запустити PWM 4,47 кГц, CCR4=50. Перевірити звук; якщо є осцилограф — період приблизно 223,5 мкс.
3. Перевірити вимкнення через приблизно 38 мс та тишу після переходу у sleep.
4. Під’єднати запити з EXTI PB6 та перевірити всі три заплановані режими індикації.

Для цих перевірок не потрібні текстури SPI-пам’яті.

## 8. Первинні довідкові визначення

Поведінка пристрою встановлена з його HEX. Назви регістрів та HAL-полів звірені з первинними ST headers:

- [STM32L051 CMSIS device header](https://github.com/STMicroelectronics/cmsis-device-l0/blob/master/Include/stm32l051xx.h): GPIO, TIM, DMA DIR/PINC/MINC, RCC.
- [STM32L0 HAL RCC](https://github.com/STMicroelectronics/stm32l0xx-hal-driver/blob/master/Inc/stm32l0xx_hal_rcc.h): PLL та clock dividers.

Відповідність PA3/AF2 і PB8 у цьому документі отримана з ініціалізації GPIO саме досліджуваної прошивки, а не з припущення за типовою схемою дозиметра.
