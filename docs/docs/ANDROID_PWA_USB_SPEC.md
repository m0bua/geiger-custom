# Технічне завдання: Android-застосунок і USB-підключення

**Статус:** узгоджене ТЗ; реалізацію відкладено до завершення поточних правок графіків.

## Мета

Надати доступ до моніторингу Geiger-2 на Android із тієї самої вебзастосункової кодової бази, з якої працює настільна версія, та дозволити встановити застосунок на головний екран із власною іконкою. Це встановлення PWA, не окремий APK.

## Підтверджений контекст

- Основний застосунок працює через браузерний протокол v1.
- На Android Chrome сторінка відкривається, але Web Serial не показує сумісного порту.
- Користувач підтвердив, що STM32Programmer на цьому самому телефоні бачить прилад.
- Для адаптера раніше фігурував USB VID/PID `10C4:EA60` (Silicon Labs CP210x). Точну модель мосту та доступні USB-інтерфейси треба зчитати з Android або перевірити при реалізації.
- Web Serial лишається транспортом для настільних браузерів. Не змінювати його поведінку під час додавання Android-шляху.

## Вимоги до Android USB-транспорту

1. Додати транспорт WebUSB для сумісного CP210x, починаючи з `10C4:EA60`, або підтвердити інший USB-ідентифікатор адаптера перед реалізацією.
2. Підключення починається лише після явної дії користувача та штатного USB-вибору браузера. Не сканувати USB автоматично.
3. Реалізувати керування CP210x через WebUSB: відкриття пристрою, вибір і захоплення потрібного інтерфейсу та bulk endpoints, налаштування UART. Протокол обміну повідомленнями v1 і декодування пакетів повторно використовуються без змін.
4. Підтримати runtime UART `115200 8N1` і ROM bootloader `115200 8E1` там, де це потрібно функціям Firmware.
5. Не перемикати RTS/DTR і не надсилати reset/bootloader-команди під час звичайного підключення. Будь-яка дія, що може змінити стан ліній або перезапустити прилад, має бути окремою, видимою та підтвердженою на реальному телефоні й адаптері.
6. Зберегти поточний Web Serial транспорт для настільних браузерів; вибирати транспорт за наявними API та сумісністю пристрою. Якщо WebUSB недоступний, показати зрозуміле повідомлення з моделлю браузера/адаптера та наступною дією.
7. Чітко показувати стани: USB-пристрій не вибрано, немає дозволу, інтерфейс зайнятий системним драйвером, помилка захоплення інтерфейсу, UART не відповідає, ROM bootloader відповідає, застосунок відповідає.
8. Після завершення сеансу звільнити USB interface/device. Повторне підключення має працювати без перезапуску телефона або перепідключення кабелю, якщо цього не вимагає ОС/драйвер.

## Вимоги до встановлення PWA

1. Публікувати застосунок на HTTPS-порталі зі стабільним origin.
2. Додати Web App Manifest з назвою, короткою назвою, `start_url`, `scope`, кольорами теми й фоном, `display: standalone`, іконками 192×192 та 512×512; за потреби додати maskable-варіант.
3. Додати service worker для кешування оболонки застосунку та основних локальних ресурсів. Показувати зрозумілий стан оновлення; не переривати активну USB-сесію автоматичним перезавантаженням сторінки.
4. Надати кнопку встановлення, коли браузер повідомляє про доступність системного install prompt; в інших випадках показати коротку інструкцію «Add to Home screen» для браузера.
5. Перевірити запуск встановленої PWA як standalone-вікна, з іконки лаунчера, а також відкриття USB-вибору після явного натискання Connect.
6. Кеш PWA не повинен застарілою версією протоколу ламати нову прошивку. Зберігати контроль версії кешу й можливість оновити оболонку.

## Спільна архітектура

- Залишити `SerialProtocol` та пакетний протокол незалежними від транспорту.
- Винести лише транспортні операції в узгоджений інтерфейс `connect/read/write/disconnect`.
- Desktop: поточний Web Serial backend.
- Android: WebUSB CP210x backend.
- Решта UI, Overview, Logs, Settings, Debug та протоколні команди лишаються спільними.
- Прошивання підтримується лише для USB-режимів, які окремо пройшли перевірку на Android. Не заявляти Quick flash або ROM flashing як підтримані до завершення відповідних апаратних випробувань.

## Перевірка сумісності та приймання

- Зафіксувати модель телефона, версію Android, версію Chrome, OTG-перехідник і USB VID/PID.
- Перевірити в Chrome у звичайній вкладці та у встановленій PWA.
- Успішне підключення має прочитати HELLO та live status, Settings, Debug і лічильники Logs.
- Перевірити кілька циклів Connect/Disconnect без reset, power-off або входу в ROM bootloader.
- Перевірити, що настільний Chrome/Edge через Web Serial працює як раніше.
- Якщо WebUSB не може захопити адаптер через системний драйвер або Android-пристрій не надає доступ до USB host API, задокументувати обмеження до розробки альтернативи; не підміняти це неперевіреним універсальним рішенням.

## Поза поточним етапом

Реалізація Android backend, PWA-маніфест/service worker, іконки, портал і публікація релізу. Це наступний етап після стабілізації графіків і окремого контрольованого тестування USB на телефоні.
