# Відкриті питання

Цей список містить питання, що лишилися після перевірки поточного прототипу.
Погоджені, але ще не реалізовані функції описано окремо в
[PRODUCT_AND_UI](PRODUCT_AND_UI.md) та [LOGS_SPEC](LOGS_SPEC.md). Попередня
реалізація журналів у `LOG_AND_STORAGE.md` збережена як історична довідка.

## Поточні наступні задачі

Базові екрани, кнопкова навігація та браузерний застосунок реалізовані.
Старі постійні журнали й відповідні графіки вилучено; зараз працюють живий
секундний журнал і CPM-графік. Перед новою реалізацією потрібно закрити
[питання специфікації журналів](LOGS_SPEC.md#9-що-ще-треба-зафіксувати).
Синхронізація часу через `SET_RTC` та вкладка Manual вже є. Актуальний

| Пріоритет | Питання | Що потрібно зробити |
|---|---|---|
| Середній | Точність і збереження часу | RTC працює після виправлення адреси `RCC_CSR` (`+0x50`, раніше помилково `APB2RSTR/+0x24`). Визначити фактичне джерело LSE/LSI, похибку ходу та поведінку після reset і повного знеструмлення. Старе `OSC L1R0` не було показом стану генератора. |
| Критичний | Перевірка керування HV | Налаштування `HV` керує PA5 за стоковими on/off-переходами; електричне навантаження PA5, зв’язок із HV та безпечна поведінка на reset/bootloader потребують перевірки на платі. Не трактувати PA5 як підтверджений HV enable. |
| Високий | Калібрування дози | Зіставити показ швидкості з контрольним джерелом і підтвердити коефіцієнт для встановленої трубки/напруги. Поточний екран використовує алгоритм, відновлений зі стоку. |
| Високий | Батарея | ADC2 відображається за формулою зі стокового аналізу. Перевірити напругу на PA2 та відповідність показаного відсотка реальному рівню заряду мультиметром; стокова шкала сама по собі не підтверджує фізичне калібрування. |
| Високий | Сонячний вхід | ADC9 реагує на вхід; показ використовує стокове `raw / 31`. Перевірити дільник і калібрування за напругою. |
| Високий | SPI NOR | На платі підтвердити JEDEC ID `C2 20 14` і стабільність запису/стирання; інші чипи поки не підтримуються. Див. драйвер `src/spi_nor.c`. |
| Середній | Повна карта GPIO | Встановити фізичні сигнали динаміка, ліхтарика та невідомих ліній. Відрізняти кодові кандидати від підтверджених доріжок. |
| Середній | LCD | Пікселі, DMA й кнопкову навігацію перевірено. Уточнити точну модель контролера, RGB/BGR-порядок та орієнтацію панелі. Див. [LCD_AND_DISPLAY](LCD_AND_DISPLAY.md) і [LCD_STOCK_GUIDE](LCD_STOCK_GUIDE.md). |
| Високий | Перевірка часу й розривів історії | Погоджені календарні епохи для великих змін RTC, порядок витіснення за записом, каскад перед стиранням і збереження історії «до встановлення часу». Перевірити їх на пристрої та деталізувати обробку прогалин після втрати незакритої хвилини; див. [LOGS_SPEC](LOGS_SPEC.md). |
| Високий | Новий рушій журналів | Спільний запит `n × m` читає від молодших джерел до старших; поточна точка доповнюється RAM раз на секунду для дисплея й застосунку. EEPROM: 62/25/100 звичайних записів та 30 алертів у межах 1 700 Б. SPI: приблизно рівні хвилинний, годинний та алертний потоки, без денного. Заголовки, CRC й транзакційні правила визначені в [LOGS_SPEC](LOGS_SPEC.md); пакування службової області ще слід перевірити. |
| Високий | Перетин EEPROM | Відкладено виправлення: `daily_dose.c` використовує 140–267, що перетинається з налаштуваннями. Заміна цієї карти не повинна займати резерв конфігурації чи розширювати область журналів понад 1 700 Б; див. розділ 5.1 [LOGS_SPEC](LOGS_SPEC.md). |
| Середній | Перевірка перенесення EEPROM → SPI | Денна історія лишається незмінним архівом EEPROM, який читає спільний рушій. Нові записи йдуть лише у SPI. Перевірити збереження архіву й відсутність подвійного врахування даних; див. [LOGS_SPEC](LOGS_SPEC.md). |
| Середній | Дампи пам'яті | Перевірити на платі читання FLASH/EEPROM через ROM `Read Memory` і повний SPI dump через `GET_SPI_DUMP_PAGE`. Переконатися, що розмір і вміст отриманих `.bin` коректні; функція описана у [`app/README.md`](../../app/README.md). |
| Середній | Застосунок | Web Serial клієнт має Overview, Logs, Settings із синхронізацією часу, Debug, Firmware, Manual та About. Відкриття порту може спричинити reboot на окремих USB-UART мостах; клієнт очікує запуску та повторює `HELLO`. Після реалізації нового рушія журнали застосунку слід перевести на спільний запит `n × m`. |
| Високий | Web Serial: reset при підключенні та прошивання через ROM bootloader | Відкриття порту додатком перезапускає прилад. Кнопка Bootloader переводить його в ROM (раніше отримували ACK), але при відкритті COM завантажувачем прошивання плата повертається до прикладної прошивки, і запис не починається. USB перепідключати не потрібно після запуску `STM32_Programmer_CLI` connect-проби — після неї PlatformIO прошиває. Див. журнал експериментів у [звіті Web Serial](APP_WEB_SERIAL_AND_CUSTOM_PROTOCOL.md). |
| Низький | Локальні опції | Вирішити, чи потрібні експорт журналу, блокування кнопок та налаштування звукового попередження. Очищення журналів через локальне меню вже реалізоване. |

## Не робити висновок завчасно

Сирі значення ADC та збіг з формулами стоку не підтверджують фізичну напругу.
GPIO, який сток перемикає під час ввімкнення, не можна вважати HV enable без
перевірки плати. Наявність робочої підсвітки не доводить справність цифрового
живлення LCD.
