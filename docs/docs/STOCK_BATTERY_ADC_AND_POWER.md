# Geiger-2 / HiStand: ADC батареї, відсотки, зарядні індикатори й вимкнення

Досліджено `Port-4.1.17(3).hex`, SHA-256 `89368e9b3d8789d641d0d9756971cea92ea10902ea8feffac604745a0791d6d0` (19 жовтня 2026 року). Розбір описує стокову прошивку. Початкові спостереження 100–120 ADC належали ранній діагностичній збірці; це не актуальне вимірювання поточного образу. Поточну реалізацію ADC і невирішені питання див. у [LCD_AND_DISPLAY.md](LCD_AND_DISPLAY.md) та [OPEN_ITEMS.md](OPEN_ITEMS.md).

## 1. Відповідь щодо сирого значення 100–120

**100–120 у кастомі не є достатнім доказом розрядженої батареї.** Сток працює з прямими 12-бітними відліками ADC, а діапазон його шкали батареї — приблизно **1295–1670**. Перед кожною серією він робить **PB10 = 1, чекає 5 ms**, а вже потім калібрує ADC та читає три канали. Після серії PB10 повертається в 0.

Тому насамперед потрібно звірити:

1. Чи відтворено керування PB10 та затримку перед вимірюванням.
2. Чи читається саме **PA2 / ADC_IN2**, а не USB або сонячний канал.
3. Чи ADC має **12 біт**, а не 8.
4. Чи результат не обрізається до `uint8_t` і не зсувається на 4 біти.
5. Чи використано достатній час вибірки та перевірено завершення conversion.

Особливо показові два приклади:

```text
1650 у 12 бітах = 0x0672.
Якщо залишити тільки молодший байт, отримаємо 0x72 = 114.
Стоковий відсоток для повного 1650 — 95%, а для помилкових 114 — нижче шкали.

1600 >> 4 = 100.
Перехід від 12-бітного результату до 8-бітного масштабу також дає числа цього порядку.
```

Це діагностичні приклади, а не встановлена причина помилки вашого кастому: його поточний ADC-код у цьому запиті не надано. Якщо 100–120 є справжнім повним 12-бітним результатом після правильного ввімкнення вимірювального тракту, потрібно перевіряти напругу на PA2, дільник, живлення та опорну напругу ADC. Саме 0% ще не розрізняє ці випадки.

## 2. Три канали та порядок їх читання

| Порядок | ADC | Ніжка | RAM у стоку | Як використовується |
| --- | --- | --- | --- | --- |
| 1 | IN2 | PA2 | `uint16 @ 0x20000464` | Батарея: %, піктограма, пороги дозволу роботи |
| 2 | IN8 | PB0 | `uint16 @ 0x20000466` | Ознака USB/зовнішнього джерела, логіка UART/пробудження, зарядний значок |
| 3 | IN9 | PB1 | `uint16 @ 0x20000468` | Сонячний вхід: %, піктограма та зарядний значок |

Вибір GPIO й каналів доведений `0x08004650` та `0x08002F9C`. Функціональна роль визначена подальшими зверненнями до трьох RAM-значень. Назва USB для другого каналу випливає також із прив’язаної до нього логіки UART; трасу до конкретного роз’єму на платі заново не прозвонювали.

GPIO PA2, PB0 і PB1 налаштовуються в analog mode без підтяжок. Вибрані канали скануються за зростанням номерів; `CHSELR = 0x304`.

**Важливо:** це не програмне перемикання номера каналу перед кожним читанням. У стоку ввімкнено discontinuous scan із кроком один канал: три послідовні `Start → Poll → GetValue` проходять IN2, IN8, IN9. При зміні режиму сканування в кастомі порядок результатів може порушитися.

## 3. Точна послідовність вимірювання

Функція **`0x08008FF0–0x080090B8`**:

```c
GPIOB.PB10 = 1;
delay_ms(5);

HAL_ADCEx_Calibration_Start(&hadc, 0);

HAL_ADC_Start(&hadc);
HAL_ADC_PollForConversion(&hadc, 1000);
battery_raw = HAL_ADC_GetValue(&hadc);

HAL_ADC_Start(&hadc);
HAL_ADC_PollForConversion(&hadc, 1000);
usb_raw = HAL_ADC_GetValue(&hadc);

HAL_ADC_Start(&hadc);
HAL_ADC_PollForConversion(&hadc, 1000);
solar_raw = HAL_ADC_GetValue(&hadc);

HAL_ADC_Stop(&hadc);
GPIOB.PB10 = 0;
delay_ms(1);

// Далі визначається режим живлення за battery_raw.
```

Адреси викликів:

| Адреса | Дія |
| --- | --- |
| `0x08009004` | GPIOB, mask `0x0400`, SET |
| `0x0800900A` | Delay 5 ms |
| `0x08009014` | Калібрування ADC |
| `0x08009018–0x08009032` | Start/Poll/Get; запис батареї |
| `0x08009034–0x08009048` | Другий результат |
| `0x0800904A–0x0800905E` | Третій результат |
| `0x08009062` | Stop ADC |
| `0x0800906C` | GPIOB, mask `0x0400`, RESET |
| `0x08009072` | Delay 1 ms |

`HAL_ADC_GetValue` за адресою `0x080051D0` прямо читає **ADC_DR, `0x40012440`**, без ділення, маскування до байта чи фільтрації.

Результати зберігаються через `STRH`: 16-бітними словами. Програмного усереднення кількох вибірок та ввімкненого hardware oversampling у цьому шляху немає.

PB10 є виходом push-pull. Те, що він обов’язково піднімається на час вимірювання, доведено кодом. Його точна фізична функція — дозвіл дільників, аналогового тракту або іншого вузла — без схеми/прозвонювання залишається невстановленою. У кастомі слід відтворити послідовність стоку перед оцінкою справності ADC.

Функція викликається на старті (`0x08003870`) та в основному циклі (`0x08003B7A`). Відсоток використовує останню серію; окремого повільного фільтра заряду немає.

Сток не перевіряє повернені статуси калібрування, Start/Poll/Stop у цій функції. У діагностиці кастому варто їх обов’язково вивести: інакше старе або невдале читання можна прийняти за реальну напругу.

## 4. Налаштування ADC і контрольні регістри

Відновлено з `0x08002F9C` та перевірено виконанням оригінального ADC init, включно з HAL і GPIO init:

| Параметр | Значення |
| --- | --- |
| Resolution | `ADC_RESOLUTION_12B` |
| Data alignment | Right |
| Scan | Forward, за зростанням номерів |
| Continuous mode | Disabled |
| Discontinuous mode | Enabled, один канал на запуск |
| Trigger | Software |
| EOC selection | Single conversion |
| Sampling time | **160.5 ADC cycles** |
| Oversampling | Disabled |
| Clock prescaler | `ADC_CLOCK_ASYNC_DIV6` |
| Low-power frequency mode | Enabled |
| DMA continuous requests | Disabled; у дослідженому читанні використовується polling |

Контрольні значення після stock init від нульового стану периферії:

| Регістр | Адреса | Значення |
| --- | --- | --- |
| ADC_CFGR1 | `0x4001240C` | `0x00011000` |
| ADC_CFGR2 | `0x40012410` | `0x00000000` |
| ADC_SMPR | `0x40012414` | `0x00000007` |
| ADC_CHSELR | `0x40012428` | `0x00000304` |
| ADC_CCR | `0x40012708` | `0x020C0000` |

Це підтверджено емуляцією записів init, а не зчитуванням реального STM. Значення CFGR2, наприклад, прямо відрізняє вимкнений oversampling від конфігурації з додатковим правим зсувом.

Для розрядності та вирівнювання достатньо перевірити `ADC_CFGR1`:

```c
bool stock_12bit = (ADC1->CFGR1 & 0x18u) == 0;
bool stock_right_aligned = (ADC1->CFGR1 & 0x20u) == 0;
```

Точне відтворення clock prescaler потребує також справного відповідного джерела тактування. Коротший sampling time, ніж у стоку, може змінити результати на високоомному дільнику; у діагностиці варто почати зі stock 160.5 cycles.

## 5. Відсоток батареї

### 5.1. Константи та формула

У RAM `0x20000078` лежить початкове `uint32 1670`, скопійоване з Flash **`0x0800FD24`**. Це верхня межа шкали. Нижня опорна точка у формулах — **1295**, а перевірка дозволеного діапазону починається з **1296**.

Для робочого діапазону:

```c
uint32_t full = 1670;

if (raw > full)
    percent = 100;
else if (raw >= 1296)
    percent = 100 - ((full - raw) * 100 / (full - 1295));
else
    percent = 0;  // логічний нижній clamp; див. баг UI нижче
```

Ділення цілочисельне. Точна форма — `100 - floor(...)`, не `floor((raw - 1295) * 100 / 375)`; вони можуть відрізнятися на один процент.

У HEX немає нелінійної Li-ion таблиці напруга→SOC у цьому ланцюгу. Це лінійна шкала ADC, а не вимірювання ємності/кулонів.

| Повний 12-бітний raw батареї | Відсоток за формулою |
| --- | --- |
| 100–120 | Нижче шкали |
| 1295 | Нижня опорна точка; звичайна робота вже не дозволена |
| 1296 | 1% |
| 1300 | 2% |
| 1330 | 10% |
| 1400 | 28% |
| 1500 | 55% |
| 1600 | 82% |
| 1636 | 91% |
| 1650 | 95% |
| 1670 і вище | 100% |

Ці пороги **не можна без додаткових вимірів назвати напругами акумулятора**. Код працює з ADC counts; коефіцієнт дільника та реальна VDDA/VREF+ не відновлені. VREFINT серед трьох вимірюваних каналів не вибраний, компенсації через його значення в цій формулі немає.

### 5.2. Баг числового екрана Energy нижче межі

Функція **`0x080094D8`** спочатку розраховує сонячний %, потім батарейний. Якщо батарея `raw < 1296`, перехід у `0x080095D8` пропускає обчислення батарейного процента. У регістрі залишається раніше обчислений сонячний процент.

Відтворено оригінальним кодом з реальним formatter:

| Battery raw | Solar raw | Solar на екрані | Battery на екрані Energy |
| --- | --- | --- | --- |
| 100 | 0 | 0% | 0% |
| 100 | 1550 | 50% | **50%** |
| 120 | 3100 | 100% | **100%** |
| 1295 | 1550 | 50% | **50%** |
| 1296 | 0 | 0% | 1% |
| 1500 | 3100 | 100% | 55% |

Отже, Energy при нижньому позашкальному читанні не є надійним еталоном. За нормальної напруги сток намагається вимкнути пристрій до роботи в цьому діапазоні, тому це не обов’язково часто видно на живому приладі.

У кастомі варто явно розділити: валідність ADC, нижній clamp до 0%, оцінку процента та дію захисту. Копіювати цю помилку Energy немає потреби.

### 5.3. Головний значок батареї — окремий алгоритм

Оригінальний головний екран `0x0800A5E0` використовує растрові ступені, а не довільний цифровий процент. Для нормального діапазону:

| Raw батареї | Індекс ступеня |
| --- | --- |
| 1296–1354 | 0 |
| 1355–1414 | 1 |
| 1415–1474 | 2 |
| 1475–1534 | 3 |
| 1535–1594 | 4 |
| 1595 і вище | 5 |

Зміщення ресурсу дорівнює `index × 578`. Нижче 1296 у цій функції залишається індекс 1 — ще одна причина не трактувати растрові ступені як точний цифровий процент. Початкове присвоєння 6 для повної батареї пізніше перекривається циклом ступенів і фактично доходить до 5.

## 6. Пороги низького заряду та вимкнення

У кінці кожного вимірювання **`0x08009076–0x080090B8`** записується режим у `uint8 @ 0x2000006C`:

| Battery raw | Режим | Подальша поведінка |
| --- | --- | --- |
| 0–1229 | 1 | Шлях вимкнення/STOP |
| 1230–1295 | 2 | Інша гілка попередження, потім той самий шлях STOP |
| 1296–4000 | 3 | Дозволена звичайна робота |
| 4001–4095 | 0 | Окрема позадіапазонна гілка; не є доказом керування зарядом або OVP батареї |

В основному циклі `0x08003B92–0x08003B9E` режими 1/2 передаються в **`0x08003648`**. Виконанням обох шляхів підтверджено досягнення виклику **`0x0800595C(1, 1)`**: низькоспоживальний STOP із WFI та low-power regulator.

На шляху вимкнення код, зокрема:

- зупиняє відповідні таймерні/UART/PWM операції;
- ставить PB2 у 0;
- ставить PA0, PA1, PA6 у 1;
- ставить PB8 у 0;
- відправляє LCD команду sleep `0x10`;
- перемикає системне тактування, призупиняє SysTick і входить у STOP.

Фізичне призначення всіх цих керувальних GPIO не встановлене, тому із самого цього переліку не слід робити висновок, який саме з них вимикає HV або від’єднує конкретне навантаження.

**Це програмний режим вимкнення, не доведене фізичне від’єднання акумулятора.** STOP зберігає RAM і має джерела пробудження. Фактичний струм у стані OFF, апаратний захист комірки та пороги захисного контролера з HEX не визначаються.

У виборі режиму немає таймера підтвердження низького заряду, усереднення чи явного гістерезису: рішення формується після поточної серії ADC. Помилкове низьке читання тому теж здатне відправити сток у shutdown path. Ця функція не надає окремого аварійного flush нового SPI-журналу кастому; таку політику потрібно реалізувати у новій прошивці.

## 7. USB, сонячний вхід і індикатор заряду

Це переважно розпізнавання наявності джерел за напругою, а не доведене читання статусу завершення заряду від charger IC.

| Умова | Кодова роль |
| --- | --- |
| Другий ADC raw **>1500** | USB/зовнішнє джерело вважається наявним; також використовується у логіці UART та виходу з екранного сну |
| Третій ADC raw **>2800** | Сонячний вхід достатній для зарядного значка |
| USB наявний і battery raw **<1651** | Варіант значка заряджання |
| USB наявний і battery raw **≥1651** | Інший варіант значка, відповідний високому рівню/завершенню за напругою |

`1651` утворюється як `full - 19`, де `full = 1670`. Це перемикання **піктограми**, а не знайдена команда припинити заряджання.

При сонячному raw >2800 зарядний варіант може вибиратися і для вже високої батареї; це ще раз показує, що іконка не є виміром зарядного струму. Якщо USB та сонячний пороги виконані одночасно, можливі послідовні виклики різних варіантів renderer.

Для сонячного процента окремо задано `full_solar = 3100` у RAM `0x2000007C`, початкове значення з Flash **`0x0800FD28`**:

```c
solar_percent = min(100, solar_raw * 100 / 3100);
```

Він показує відносний рівень ADC сонячного входу. Це не відсоток зарядного струму, потужності або ефективності панелі.

У досліджених шляхах не знайдено алгоритму CC/CV, задання зарядного струму, вимірювання струму акумулятора чи окремої температурної комірки ADC. Чи виконує відповідні функції зовнішній аналоговий charger/protection IC, без визначення його моделі та схеми сказати не можна.

## 8. Практична перевірка кастому без зміни формули навмання

1. Увімкнути analog mode для PA2/PB0/PB1. Переконатися у 12 бітах, right alignment, відсутності oversampling shift, достатньому sampling time.
2. Підняти PB10 і витримати щонайменше stock **5 ms**.
3. Зняти три коректно завершені conversion у визначеному порядку. Для першої діагностики використати послідовність стоку з discontinuous forward scan.
4. Зберегти результати в `uint16_t[3]` або ширші змінні. Вивести повні числа та hex, наприклад `battery=1650 / 0x0672`. Не обмежуватися байтовим буфером чи `%hhu`.
5. Окремо вивести статуси калібрування/Start/Poll і регістри CFGR1, CFGR2, SMPR, CHSELR, CCR. Зчитувати DR після завершення conversion.
6. Повернути PB10 у 0 після всієї серії.
7. Порівняти батарейне значення з діапазоном стоку. Лише після підтвердження ADC застосовувати шкалу %, робити висновки про заряд та налаштовувати автоматичне вимкнення.

Для швидкого журналу налагодження достатньо такого набору:

```text
PB10 during sample
ADC CFGR1 / CFGR2 / SMPR / CHSELR / CCR
calibration status
Start/Poll status для кожного conversion
PA2 full raw dec + hex
PB0 full raw dec + hex
PB1 full raw dec + hex
```

Якщо після цього PA2 усе ще дає 100–120, наступна перевірка — фактична напруга комірки та PA2/VDDA. Константи 1295/1670 не слід підганяти під 100–120 до встановлення причини різниці масштабу.

## 9. Докази та межі перевірки

У Unicorn 2.1.4 виконано оригінальні Thumb-функції з дослідженого HEX:

- ADC init з реальними HAL/GPIO записами; підтверджено конфігурацію регістрів.
- Вимірювальну функцію з підставленими результатами периферії; підтверджено PB10 high → 5 ms → три результати → PB10 low → 1 ms та RAM-порядок.
- Режими для 0, 100, 120, 1229, 1230, 1295, 1296, 1670, 4000, 4001, 4095.
- Energy з оригінальним форматуванням: нормальну шкалу та повторення solar % нижче battery-порогу.
- Вибір піктограм на межах USB 1500/1501, solar 2800/2801 та battery 1650/1651.
- Обидва низьковольтні шляхи до STOP; фізичні ефекти периферії в цій ізольованій перевірці замінювалися заглушками.

Реальний кастом, ADC-напруги на платі, стан комірки й фізичний charger/protection IC не вимірювалися. Тому встановлено, **що саме очікує та робить сток**, але не оголошено конкретну причину ваших 100–120 без його ADC-коду або контрольних вимірів.

Первинні технічні джерела для розшифрування периферійних полів:

- [ST: STM32L0 HAL ADC header](https://raw.githubusercontent.com/STMicroelectronics/stm32l0xx-hal-driver/master/Inc/stm32l0xx_hal_adc.h).
- [ST: STM32L051x6/x8 datasheet](https://www.st.com/content/ccc/resource/technical/document/datasheet/9a/75/bd/16/0f/fd/49/19/DM00108219.pdf/files/DM00108219.pdf/jcr:content/translations/en.DM00108219.pdf).

Порогові константи, формули, GPIO-послідовності та переходи режимів отримані безпосередньо з HEX; даташіт і HAL використовуються для значення назв каналів, бітів і режимів.
