# Handoff: збірка та стан прошивки

## Платформа

- MCU: STM32L051C8T6.
- Bare-metal C, без Arduino та STM32 HAL.
- Основне середовище: VS Code + PlatformIO.
- Конфігурація `platformio.local.ini` локальна й ігнорується Git; у ній зараз
  задано UART bootloader на COM4. Для завантаження вручну перевести прилад у БЛ.
- За замовчуванням у репозиторії лишається ST-LINK/SWD upload profile.

Збірка з кореня репозиторію:

```powershell
pio run
```

Артефакти з’являються в `.pio/build/geiger2/`. Для прошивання:

```powershell
pio run --target upload
```

Переконайтеся, що вибраний локальний upload profile відповідає підключенню
програматора та режиму плати.

## Стан на 2026-10-21 — виправлення RTC підтверджене на платі

- Знайдено причину `OSC`: `RCC_CSR` був помилково адресований як
  `RCC_BASE + 0x24` замість `+0x50`. За `+0x24` знаходиться `APB2RSTR`;
  запис «LSION» встановлював `SYSCFGRST`, а не запускав генератор.
  Попереднє `L1R0` читалося з регістра reset і не свідчило про стан LSI.
- Адресу виправлено в доступах і очікуванні прапорців. Backup reset перенесено
  перед запуском LSE, додано перевірку доступу DBP, стану збереженої конфігурації
  й синхронізацію RTC після reset. Читання календаря завершується `DR`, щоб не
  залишати тіньовий регістр дати заблокованим. Збірка успішна; користувач
  підтвердив, що виправлений годинник запрацював на платі.
- Користувач також підтвердив, що лічильник автоматично запрацював після цього
  виправлення. Ймовірна причина — запис у `SYSCFGRST` скидав маршрутизацію
  EXTI6 з PB6 на PA6. Отже, збій RTC та лічильника мав спільну причину в адресі
  RCC; залежність підрахунку від ходу RTC не потрібна для цього пояснення.
- У DEBUG рядок 2 показує `LSI L1R1 A1B1 M1F1` при успішному запуску від LSI
  або починається з `LSE`, якщо вибрано кварц. `L/R` — справжні LSION/LSIRDY
  (при LSE вони можуть бути нульовими), `A` — latch PA5, `B` — рівень PB6,
  `M/F` — EXTI mask/falling-edge enable. Помилки: `OSC`, `INT`, `SYC`, `DBP`.
- Стартовий сплеск прибраний відкладеним керуванням PA5; не повертати раннє
  ввімкнення без окремої перевірки, воно пов’язане зі стартовими артефактами.
- Уточнити фактичне джерело тактування (`LSE` або `LSI`), похибку ходу та
  поведінку календаря після reset і повного знеструмлення. LSI має номінальний,
  а не відкалібрований дільник.

Адреси й біти звірені з [офіційним CMSIS-заголовком STM32L051](https://github.com/STMicroelectronics/cmsis-device-l0/blob/master/Include/stm32l051xx.h).

## Що вже реалізовано й перевірено

### Застосунок і serial-підключення — дослідження 2026-10-22

- У репозиторії є початковий Web Serial клієнт і протокол v1 (`app/`, `src/protocol_v1.c`, `include/protocol_v1.h`); фізичний стабільний обмін ще не підтверджений.
- Web Serial експерименти: без `setSignals()` пристрій лишався неактивним до закриття порту; тестовані post-open RTS/DTR послідовності заводили його в bootloader.
- Окремий native Win32 probe з профілем 115200 8E1 на COM3 відкрив і закрив порт без reboot. Це одиничний результат для цієї ОС/плати/адаптера, не універсальна гарантія.
- Боротьбу з reboot наразі відкладено. Пізніше розглянути дві опції: Web Serial із прийнятним reboot/reconnect або OS-specific native transport. Не перебирати RTS/DTR навмання.
- Повний контекст, послідовності й обмеження: [звіт про Web Serial і протокол](GEIGER2_STOCK_APP_WEB_SERIAL_AND_CUSTOM_PROTOCOL_2026-10-21.md).

- Дисплей 160×80: стокова init-послідовність, SPI2 та швидка заливка через DMA.
- Два головні екрани з ADC-заголовком: µSv/h + CPM та накопичена доза;
  коротке праве натискання перемикає їх, коротке ліве циклічно перемикає
  режими `NORMAL → SEARCH → INVISIBLE`.
- Довге праве натискання відкриває додаткові екрани `TIME → SETTINGS → DEBUG`;
  короткі право/ліво гортають їх, довге ліве повертає на попередній головний
  екран. Переходи повністю очищають видиму область.
- TIME-екран, меню редагування Year/Month/Day/Hour/Minute та RTC реалізовані;
  користувач підтвердив роботу годинника після виправлення адреси RCC.
- Підрахунок імпульсів автоматично відновився після виправлення RCC; причина
  узгоджується з відновленням маршрутизації EXTI6 через SYSCFG.
- PB6/EXTI6, обробник імпульсів та підрахунок на платі підтверджені; фізичне
  калібрування швидкості/дози лишається окремою перевіркою.
- ADC2/ADC8/ADC9 з індикацією для перевірки. Фізичні калібрування ще не
  підтверджені.
- Кнопки PB9/PA4; натискання вмикає підсвітку, а коротка дія виконується
  одночасно з пробудженням.
- Підсвітка PB2 стартує вимкненою й вимикається через 10 секунд бездіяльності.

Деталі розділені між [LCD_AND_DISPLAY](LCD_AND_DISPLAY.md),
[STOCK_FIRMWARE](STOCK_FIRMWARE.md) та [STOCK_RATE_DOSE](STOCK_RATE_DOSE.md).

## Наступні перевірки

1. Порівняти підрахунок з незалежним приладом на довшому інтервалі та
   відкалібрувати коефіцієнт дози.
2. Виміряти батарейний і сонячний ADC-дивідери мультиметром.
3. З’ясувати безпечне керування HV і фізичне призначення GPIO-кандидатів.
4. Підтвердити тип та геометрію SPI NOR до запису даних.
5. Після апаратних вимірювань продовжити журналювання, збереження дози й
   протокол застосунку.

Трубка SBM-20-1 та орієнтир 400 V повідомлені користувачем; це не є
підтвердженням схеми HV або її поточного стану. Не перемикати невідомі GPIO
навмання.
