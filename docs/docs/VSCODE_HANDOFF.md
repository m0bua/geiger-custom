# Handoff: збірка та стан прошивки

## Платформа

- MCU: STM32L051C8T6.
- Bare-metal C, без Arduino та STM32 HAL.
- Основне середовище: VS Code + PlatformIO.
- Конфігурація `platformio.local.ini` локальна й ігнорується Git; у ній зараз
  задано UART bootloader на COM4. Для завантаження вручну перевести прилад у БЛ.
- За замовчуванням у репозиторії лишається ST-LINK/SWD upload profile.

Збірка з кореня репозиторію:

```powershell
pio run
```

Артефакти з’являються в `.pio/build/geiger2/`. Для прошивання:

```powershell
pio run --target upload
```

Переконайтеся, що вибраний локальний upload profile відповідає підключенню
програматора та режиму плати.

## Стан на 2026-10-20 — потрібне продовження налагодження

- Остання збірка компілюється, але RTC ще не працює: збереження календаря
  завершується `OSC`. Діагностичний екран показав `L1R0` (LSI увімкнений,
  прапорець готовності не встановлений). У коді виправлено біти `RTCEN`/
  `RTCRST` згідно з STM32L051, але виправлення на пристрої ще не підтверджене.
- Підрахунок спрацювань не вважається робочим: користувач бачить `00` у
  прогресбарі й не спостерігає подій. Фото DEBUG показало `CNT 1`, однак це
  сирий лічильник від старту; головний екран встановлює базову точку після
  ініціалізації, тож таке значення може бути стартовим імпульсом, не врахованим
  у поточній сесії. Не робити висновок, що вимірювання відновлено.
- У DEBUG рядок 2 тимчасово замінений діагностикою `OSC L1R0 A1B1 M1F1`:
  `L/R` — LSION/LSIRDY, `A` — вихідний latch PA5 (ODR, не виміряний рівень на
  виводі), `B` — рівень PB6, `M/F` — EXTI mask/falling-edge enable.
- Стартовий сплеск прибраний відкладеним керуванням PA5; не повертати раннє
  ввімкнення без окремої перевірки, воно пов’язане зі стартовими артефактами.
- Завтра спершу перевірити RTC register setup і шлях імпульсів окремо. Не
  вважати `OSC` або нульовий прогресбар виправленими лише через успішну збірку.

## Що вже реалізовано й перевірено

- Дисплей 160×80: стокова init-послідовність, SPI2 та швидка заливка через DMA.
- Два головні екрани з ADC-заголовком: µSv/h + CPM та накопичена доза;
  коротке праве натискання перемикає їх, коротке ліве циклічно перемикає
  режими `NORMAL → SEARCH → INVISIBLE`.
- Довге праве натискання відкриває додаткові екрани `TIME → SETTINGS → DEBUG`;
  короткі право/ліво гортають їх, довге ліве повертає на попередній головний
  екран. Переходи повністю очищають видиму область.
- TIME-екран і меню редагування Year/Month/Day/Hour/Minute реалізовані, але
  запис і хід RTC не підтверджені через поточний `OSC`; див. статус вище.
- PB6/EXTI6 та обробник імпульсів є в коді, але поточний підрахунок на приладі
  не підтверджений; див. статус вище.
- ADC2/ADC8/ADC9 з індикацією для перевірки. Фізичні калібрування ще не
  підтверджені.
- Кнопки PB9/PA4; натискання вмикає підсвітку, а коротка дія виконується
  одночасно з пробудженням.
- Підсвітка PB2 стартує вимкненою й вимикається через 10 секунд бездіяльності.

Деталі розділені між [LCD_AND_DISPLAY](LCD_AND_DISPLAY.md),
[STOCK_FIRMWARE](STOCK_FIRMWARE.md) та [STOCK_RATE_DOSE](STOCK_RATE_DOSE.md).

## Наступні перевірки

1. Порівняти підрахунок з незалежним приладом на довшому інтервалі та
   відкалібрувати коефіцієнт дози.
2. Виміряти батарейний і сонячний ADC-дивідери мультиметром.
3. З’ясувати безпечне керування HV і фізичне призначення GPIO-кандидатів.
4. Підтвердити тип та геометрію SPI NOR до запису даних.
5. Після апаратних вимірювань продовжити журналювання, збереження дози й
   протокол застосунку.

Трубка SBM-20-1 та орієнтир 400 V повідомлені користувачем; це не є
підтвердженням схеми HV або її поточного стану. Не перемикати невідомі GPIO
навмання.
